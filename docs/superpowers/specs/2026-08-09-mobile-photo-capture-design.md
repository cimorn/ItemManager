# 手机扫码拍照设计

## 目标

在物品编辑窗口中提供手机扫码拍照。手机和电脑连接同一局域网，照片直接传到当前编辑窗口。照片在物品保存前只保存在内存中；用户保存物品后，软件才把照片写入项目图片目录。

## 用户流程

1. 用户先填写物品名称、分类、位置等信息。
2. 用户点击图片区的“手机拍照”。
3. 软件临时启动局域网拍照服务，并显示二维码。
4. 手机扫码后打开拍照页，调用后置摄像头拍照。
5. 手机可预览、重拍，并把确认的照片发送到电脑。
6. 电脑显示照片预览和“待保存”状态。再次发送照片时，最新照片替换旧缓存。
7. 用户点击物品“保存”，软件按当前分类生成路径并写入 WebP 图片。
8. 用户取消或关闭编辑时，软件丢弃缓存，不创建图片文件。

原有“选择图片”功能保持不变。

## 界面

物品编辑窗口在“选择图片”旁增加“手机拍照”按钮。点击后，图片区显示二维码、局域网地址、剩余有效时间和连接状态。收到照片后，二维码区域收起，图片预览显示“待保存”。

手机页只包含拍照、照片预览、重拍和“发送到电脑”。手机页不读取物品名称、分类、位置、标签或其他项目数据。

## 组件边界

### 局域网拍照服务

Electron 主进程按需启动 HTTP 服务并监听可用局域网地址。服务创建随机会话令牌，返回二维码地址，并接收手机上传的照片。没有活动会话时，服务自动关闭。

### 手机拍照页

手机页使用系统文件拍照控件调用后置摄像头。页面在手机端把照片压缩为最长边 1600 像素、质量 0.78 的 WebP，再上传到当前会话。

### 编辑窗口缓存

主进程收到照片后，通过 IPC 把照片交给当前编辑窗口。编辑窗口仅保存照片数据、文件类型和大小，不提前创建文件。每个编辑窗口最多保留一张待保存照片。

### 图片落盘

物品保存时，编辑窗口把缓存照片、项目目录和当前分类路径交给主进程。主进程生成文件名并写入：

`data/images/一级分类/二级分类/分类-子分类-时间.webp`

写入成功后，软件把相对路径写入物品的 `imagePath`。写入失败时，物品窗口保持打开并显示错误，用户可以重试。

## 数据与安全

- 拍照服务只绑定当前电脑的局域网接口，不创建公网地址。
- 每个会话使用高强度随机令牌，10 分钟后失效。
- 服务只接受当前有效会话的图片上传，始终用最新照片替换旧缓存，并限制请求体大小和图片类型。
- 手机不能指定项目目录、分类目录或文件名。
- 保存、取消、会话过期和窗口关闭都会清理对应内存缓存。
- 软件退出后，所有未保存照片自动消失。

## 异常处理

- 找不到可用局域网地址时，提示检查 Wi-Fi 或有线网络。
- 手机无法打开页面时，提示确认两台设备连接同一局域网，并允许 Windows 专用网络访问。
- 二维码过期后，用户可点击“重新生成”。
- 手机上传失败时，保留手机预览并允许重试。
- 用户未选择分类时，可以拍照和预览，但保存前必须选择分类。

## 测试范围

- 会话创建、随机令牌、过期和清理。
- 图片类型、大小和无效令牌校验。
- 手机发送后只产生内存缓存，不创建正式文件。
- 保存后写入正确分类目录并更新 `imagePath`。
- 取消、关闭和重新拍照时不留下多余文件。
- 物品编辑窗口的二维码、等待、待保存和失败状态。
- 打包后的 Windows 软件可启动拍照服务并完成一次扫码拍照流程。
